## 3. Ключевые дизайн-решения сессии

### 3.1. Кейс ≠ продукт (редизайн «галерея»)
Страница кейса изначально повторяла язык питч-дека (палитра, Fraunces, композиция) → путница у зрителя. Решение владельца — вариант А:
- светлая тема: бумага `#f3ede0`, тушь `#211a11`, киноварь тонким акцентом;
- дисплейное лицо — **Newsreader** (нативный italic + кириллица), подписи — **IBM Plex Mono**, тело — Inter;
- **артефакты deck сохранены тёмными** (свотчи палитры + мини-деки с родным Fraunces) — на светлом фоне читаются как экспонаты продукта внутри рассказа;
- реализация: токены `.theme-kunfu` переписаны + SKIN-слой оверрайдов в конце `globals.css` (инверсия ролей `--case-ink`/`--case-paper`, ink-линии вместо paper-линий); все прежние точечные правки сохранены.

### 3.2. Финансовый экран (секция 05)
Ветка исследована прямо в бандле презентации: 11 суб-слайдов (Допущения → Юнит-экономика → Маржа тура → Расходы → Сметы → Доходы → P&L → Безубыточность → Инвестору → Сценарии → Риски). В кейсе отражены **реальные цифры ветки**: Год 8 — полная окупаемость (базовый сценарий), маржа 15–25% в зрелой фазе, ~15 млн ₽ накопленной прибыли к 10-му году, сценарии −6/+2/+9. «Результат» перенумерован в 06.

## 4. Технические заметки для будущих сессий
- **Каскад:** все правки кейса делаются оверрайдами в конце `app/globals.css` ПОСЛЕ мигрированного блока — позиция в файле решает; мигрированный блок не трогать.
- **lightningcss/Turbopack** переставляет и минифицирует декларации — при проверке собранного CSS искать по селектору и позициям вхождений, а не по буквенной строке.
- **Статический экспорт:** картинки/ссылки на ассеты через `asset()` (basePath); внутренние переходы — `next/link`, внешние — `target="_blank" rel="noopener noreferrer"`.
- **Деплой:** push в main → GitHub Actions → och-studio.ru (~60–90 с); после пуша проверять страницу с `?v=$RANDOM` и новый css-чанк напрямую.
- Memory bank обновлялся после каждого этапа (разделы «Выполнено 23.08.2026…» в `activeContext.md`).
